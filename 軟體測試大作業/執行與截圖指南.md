## 一、Postman（在瀏覽器直接跑，直接截圖）

集合與環境**已經建立在你的 Postman 帳號**（工作區：`linm li's Workspace`）：
- Collection：**AutomationExercise API**（14 支 API，每支都含自動化斷言）
- Environment：**AutomationExercise Env**（含 `baseUrl`）

### 在瀏覽器執行步驟
1. 開啟瀏覽器登入 https://go.postman.co （用 linmli729@gmail.com 帳號）。
2. 左側 **Collections** → 點 **AutomationExercise API**。
3. 右上角環境下拉選 **AutomationExercise Env**。
4. 點 Collection 名稱右側 **Run**（或 ⋯ → Run collection）進入 **Collection Runner**。
5. 保持 14 個請求勾選，按 **Run AutomationExercise API**。
6. 跑完會看到每支 API 綠色 **PASS**（共 28 個斷言全通過）→ **截圖即為「圖3-1 Postman 執行結果」**。

### 設計重點（寫進報告會加分）
- Automation Exercise 的 API 一律回 **HTTP 200**，真正狀態碼放在回應 JSON 的 **`responseCode`** 欄位，因此斷言驗證的是 `responseCode` 與 `message`（非 HTTP 狀態列）。
- 帳號類 API 已串成生命週期並排序：**建立(API11) → 驗證登入(API7) → 更新(API13) → 查詢(API14) → 刪除(API12)**；建立時用時間戳產生唯一 email，故每次整跑都會全綠、可重複執行。

### 斷言範例（API7 驗證登入）
```javascript
let json = pm.response.json();
pm.test("responseCode 為 200", () => pm.expect(json.responseCode).to.eql(200));
pm.test("訊息: User exists!", () => pm.expect(json.message).to.eql("User exists!"));
```

> 備援：若需重新匯入，可用本資料夾的 `Postman_AutomationExercise_Collection.json`（File → Import）。

## 二、JMeter（直接跑，直接截圖 Aggregate Report）

檔案：本資料夾的 `AutomationExercise_效能測試.jmx`

### 執行步驟
1. 安裝 JDK 8+ 與 Apache JMeter（解壓後執行 `bin/jmeter`，Windows 用 `jmeter.bat`）。
2. **File → Open** 選擇 `AutomationExercise_效能測試.jmx`。
3. 內含 5 個場景（已對應報告表3-3），並已勾選「序列化執行緒群組」會依序執行：

| 場景 | 目標 API | 執行緒數 | Ramp-up(秒) | 迴圈 |
|---|---|---|---|---|
| S1 單使用者基準 | GET /productsList | 1 | 1 | 10 |
| S2 輕量併發 | GET /productsList | 10 | 5 | 10 |
| S3 中度併發 | POST /searchProduct | 50 | 10 | 5 |
| S4 高度併發 | POST /searchProduct | 100 | 15 | 5 |
| S5 持續壓力 | GET /productsList | 30 | 10 | 20 |

4. 已內建三個 Listener：**Aggregate Report**、**Summary Report**、**View Results Tree**。
5. 按上方綠色 ▶ 執行；跑完點 **Aggregate Report** → **截圖即為「圖3-2 彙總報告」**（含 Average、Throughput、Error%）。
6. 若只想單獨跑某場景：在左樹對其他 ThreadGroup 按右鍵 → **Disable**，只留一個 Enable 再跑，逐一截圖。
7. 截圖前建議按工具列掃帚圖示 **Clear All** 清空舊數據，避免混入前一場景。

> 提示：高併發(S4=100 緒)若本機資源不足，可調低執行緒數分批測，並在報告 5.1 風險評估說明（符合作業要求）。

### B. 自動化執行：Selenium（可自動截圖）
`selenium/` 資料夾提供 6 支關鍵流程自動化（註冊/登入/搜尋/購物車/聯絡/訂閱），
每支跑完自動截圖到 `selenium/screenshots/`：
```bash
cd 軟體測試大作業/selenium
pip install -r requirements.txt
pytest -v --html=report.html --self-contained-html
```
終端機 PASSED/FAILED 結果或 `report.html` 即可截圖作為自動化證明。詳見 `selenium/README.md`。

> 安全性案例（如 TC-040 SQL 注入、XSS）建議手動驗證：登入應失敗且**不**外洩資料庫錯誤、腳本不被執行。
